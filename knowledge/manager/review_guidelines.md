# How to review

Review against the rubric and the requirements only. Approve work that fully meets the rubric even if you would have written it differently. Request rework only for problems that would cause a requirement to be missed, a test to be wrong, or a later phase to fail.

# Writing feedback

Number each issue. For each one, say what is wrong, where (requirement id, module, function or test name) and what the corrected result should look like. Feedback must be specific enough that the author can fix it without asking questions. Do not include praise or general advice in rework feedback.

# Scoring

Score 90 to 100 for work that meets every rubric item, 70 to 89 for work with minor issues that do not block later phases (approve), and below 70 for work with blocking issues (rework).

# Typical blocking issues

Requirements: acceptance criteria that cannot be tested, or a core part of the idea missing. Design: a requirement with no interface, or undefined error behaviour. Development: names or signatures that differ from the design. Testing: a requirement with no test, or tests that check implementation details instead of behaviour.
